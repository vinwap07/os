## Архитектура фон Неймана
Это классический принцип организации компьютерных систем, в основе которого лежит совместное хранение команд и данных в одном общем блоке памяти. 

### Принципы фон Неймана (работа процессора и памяти)
- **Принцип программного управления**. Программа представляет собой упорядоченную последовательность команд, хранящуюся в памяти. Процессор выполняет команды одну за другой, начиная с адреса, указанного в счетчике команды. Исключениями являются явные изменения потока (вызовы подпрограмм, переходы)
- **Принцип условного перехода**. Команды из программы могут выполняться не только одна за другой. Могут существовать команды условного перехода (if-else), которые изменяют последовательность выполнения команд в зависимости от значений данных
> Обычно процессоры при if-else просто проверяют значение 0 или не 0
- **Принцип двоичности**. Все данные в памяти должны храниться в двоичном виде
- **Принцип однородности памяти**. Команды и данные хранятся в одной памяти. Над командами можно выполнять такие же действия, как и над данными.
> Современные компьютеры одновременно как подчинаются данному принципу, так и нарушают его. В современном компьютере память делится на зоны. "Договариваются", что в определенной зоне будут храниться определенные типы данных (команды, константы и т. д.)

- **Принцип адресуемости памяти**. Основная память состоит из пронумерованных ячеек. Процессору в произвольный момент времени доступна любая ячейка 

### Ограничения архитектуры фон Неймана: 
- **Бутылочное горлышко**. Если мы считаем память однородной, то процессору при выполнении каждой команды надо каждый раз обращаться к памяти, чтобы взять данные, а затем снова обратиться к ней, чтобы уже записать их. При обращении к памяти тратится много времени, намного больше, чем процессор выполняет саму команду. Эту проблему на данный момент решают при помощи кэша внутри процессора, который физически намного ближе к процессору.
- **Cамомодифицирующийся код**. Так как данные и команды находятся в одной памяти, то можно изменить код ошибки - по ошибке или специально. До разделения памяти на зоны были популярны вирусы, переписывающие код программ.

## Центральный процессор (ЦП, CPU) 
`Центральный процессор  (central processing unit)` - основное вычислительное устройство компьютера, выполняющее инструкции программы, обарабатывающее данные и управляющиее другими компонентами системы.

Внутри процессора находится набор команд, который он может выполнять - `архитектура набора команд`.

Говоря о процессоре, можно встретить такие термины: 
- `Разрядность` (16, 32, 64 bit). Объем данных в битах, который процессор может обрабатывать за один рабочий такт. 
- `Регистры` (память процессора). Сверхбыстрая ячейка внутренней памяти центрального процессора, которая одновременно хранит данные, адреса и команды для текущих вычислений.  
- `Прерывания`. Остановка выполнения текущей команды для выполнения другой команды.
> Без прерываний невозможно представить компьютер, в котором одновременно работают несколько приложений. Благодаря прерываниям даже старые компьютеры с одним ядром, с одним потоком могли вести работу нескольких приложений
- `Пошаговое исполнение (такт)`. Внутри компьютера существует тактовый генератор, генерирующий электрическое напряжение. Процессор выполняет одну операцию в один такт. За счет тактов происходит синхронизация между элементами компьютера. Также существует понятие `тактовая частота` - число тактов, которые процессор выполняет за одну секунду (ГГц)

### Виды архитектур набора команд
#### CISC (Complex Instruction Set Computer)
Процессор может исполнять какие-то базовые команды. Мы можем ускорить выполнение каких-то конкретных задач за счет определенной программы. Появляется соблазн добавить данную программу в сам процессор. 

> *Пример:* существовал процессор Pentium 166 МГц. После него появился процессор Pentium MMX (Multi Media Extensions), который внутри себя включал команды для работы с мультимедиа. 

Такие процессоры начали называть `процессорами со сложными инструкциями`. 

Другой особенностью таких процессоров была переменная длина команд. 

> Команда безусловного перехода (JMP) требует только код операции и адрес назначения (3 байта). Команда сложения двух чисел в памяти (ADD) требует код операции, адреса первого и второго аргументов (5 байт)

***Главная проблема:*** где кончается одна команда и начинается другая?

Так как в памяти все хранится в виде непрерывного потока байт, процессору на уровне электроники крайне сложно понять, где проходит граница между инструкциями. Возникает опасность сдвига и фатальной ошибки декодирования.  

Реализовывать обработку огромных и сложных инструкций напрямую на аппаратных транзисторах физически невозможно - схема получается слишком громоздкой. Поэтому внутри CISC-процессора используется `микрокод`. Каждая сложная команда, поступающая извне, на самом деле является не просто элементарным действием, а аналогом "вызова функции".

**Регистровый голод**. Площадь кристалла процессора ограничена технологическим процессом. Чем сложнее система команд и чем больше транзисторов уходит на логику декодирования и микрокод, тем меньше физического пространства остается в регистровой памяти. А чем меньше регистров, тем чаще приходится обращаться к оперативной памяти, что является узким горлышком.

> **Прикол:** На языке программирования C можно написать код, работающий чисто на регистрах, без использования оперативной памяти. 
```c
register int a = 5;
register int b = 10;
register int c = a + b;
```

**Уязвимости кэша и проблемы безопасности**. Исторически процессоры оптимизировались под максимальную скорость, из-за чего архитекторы упустили критическую брешь в безопасности: *данные предыдущих программ оставались в кэш-памяти*. 

Чтобы решить данну проблему пришлось внедрить механизм, очищающий кэш после каждой программы, что резко уменьшило производительность процессора на 15-20%.

#### RISC (Reduced Instruction Set Computer)
Анализируя проблемы подхода выше придумали новый подход - RISC
- Простые команды
- Команды имеют фиксированную длину и формат
- Любые операции вида "изменить" выполняются только над содержимым регистров, а уже из регистров данные выгружаются в память
- Большое количество регистров общего назначения
- Отсуствие микропрограмм (микрокода) внутри самого процессора

Возникает резонный вопрос: если в RISC нет сложных специализированных команд, как решать тяжелые мультимедийные например задачи? 

Решение: перенос интеллекта из железа в софт (умные компиляторы). Оказалось, что хорошему компилятору проще составить максимально эффективную последовательность из множества простых RISC-команд, чем человеку или процессору пытаться эффективно использовать одну громоздкую CIRS-команду.  

### Классы машинных инструкций
> Словестные обозначения команд взяты из ассемблера

- Перемещение. `MOV`, `PUSH`, `POP`
- Арифметические. `ADD`, `SUB`, `MUL`, `DIV`
- Логические и побитовые. `AND`, `OR`, `XOR`, `SHL`, `SHR`, `TEST`
- Ввод\вывод. `IN`, `OUT`
- Управление потоком. `JMP`, `JZ` (jump if zero), `JNZ` (jump if not zero), `CALL`, `RET`

> **Отличие JMP и CALL**. При `JMP` просто переходится в другое место, а в `CALL` запомниается место откуда идет вызов, после вызова идет возврат обратно

### Запуск компьютера
При запуске компьютера первым делом отрабатывает `BIOS` из flash-памяти. 

> Раньше не продавали компьютеры готовыми, любители собирали их самостоятельно по инструкциям из журналов. Чтобы компьютер начал работать ему все же нужен BIOS. Конечно любитель сам этот BIOS писать не будет. Поэтому в журналах реально писали длинный шестнадцатеричный код, который переписывали руками. 

Что происходит при запуске компьютера? 
1. Блок питания преобразует переменный ток (220 В) в постоянный. 
2. Блок питания проводит внутреннее тестирования. Если напряжение стабильно, он отправляет на материнскую плату специальный логический сигнал Power Good.
3. Активируется тактовый генератор, который начинает посылать ритмичные импульсы (такты) для синхронизации работ всех микросхем. 
4. Сброс процессора - все регистры пустые, кроме регистра указателя команд.
5. Работа BIOS, самотестирование оборудования. 
6. Запуск операционной системы.  

> Напомним что , процессор ничего, кроме изменения памяти не занимается. Можно сказать, что процессор обрабатывает ввод и вывод, но на деле у процессора просто есть специальные ячейки памяти для ввода и вывода, с которыми процессор работает как обычно - прочитать и записать.

## прерывания

существуют прерывания (когда команда перестает свое выполнение на время)

типы прерываний: 
- внешние - когда например сам пользователь нажимает на клавишу, двигает мышкой - процессору надо обработать это действие мгновенно
- ошибки - в процесс выполнения команды происходит недопустимое действие (например, деление на 0), тогда команда прерывается
- внутренние - благодаря ним работают функции. если goto не сохраняет место вызова и идет просто по адресу, то такое внутреннее прерывание запоминает место, может вызвать функцию извне и продолжить выполнение команды

при прерывании 
- сохраняется контекст
- получается номер прерывания
- находится ISR 
- выполняется ISR
